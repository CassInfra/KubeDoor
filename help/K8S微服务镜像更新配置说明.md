# K8S 微服务镜像更新配置说明

镜像更新规则和仓库凭据在 **系统管理 → 镜像管理** 中维护，保存到 PostgreSQL，保存后立即生效。只有系统管理员能查看或修改这些设置；安装配置和 ConfigMap 不再保存它们。

## 页面入口

| 入口 | 用途 |
|---|---|
| 系统管理 → 镜像管理 → 镜像更新规则 | 配置只读账号能在哪些集群、哪些时段更新镜像 |
| 系统管理 → 镜像管理 → 镜像仓库凭据 | 配置华为云 SWR、阿里云 ACR、Harbor 的查询凭据 |
| 资源管理 → Deployment → 操作 → 更新 | 查看镜像标签，提交新标签并触发滚动更新 |
| Agent 管理 → 更新 | 升级该集群的 kubedoor-agent 自身，只需输入标签 |

## 镜像更新规则

此处配置的是**只读账号的例外授权**。已有「更新镜像」权限的账号直接按「系统管理 → 权限与审批」执行，不受这里的时间段限制；对集群没有访问权限的账号不能使用例外授权。AI 助手、企微机器人和外部 MCP 更新镜像仍需要该账号具备「更新镜像」权限，不使用只读例外。

在「镜像更新规则」中增加或编辑一行：

| 字段 | 如何填写 |
|---|---|
| 集群 | 选择目标集群，或填写其 `K8S_NAME`；`default` 是没有专属规则的集群使用的默认规则 |
| 允许更新 | 开启后，指定的只读账号才能在允许时段更新；关闭后拒绝该集群的只读例外请求 |
| 开始 / 结束时间 | 按北京时间填写，包含开始时间、不包含结束时间；开始晚于结束表示跨零点，`00:00` 至 `24:00` 表示全天 |
| 允许账号 | KubeDoor 登录用户名，本地和 LDAP 账号均可，不区分大小写 |

默认规则初始关闭。集群有专属规则时，整条专属规则优先，不再叠加默认规则。开启规则时必须填写账号和有效时间；开始、结束时间相同不表示全天允许。

开始时间为 `00:00` 至 `23:59`，结束时间还可选 `24:00`，表示当天结束。旧配置中开始与结束相同的规则会按原本“始终不允许”的含义迁为关闭状态。

例如：为 `prod-a` 开启规则，时间 `20:00` 至 `08:00`，账号选 `zhangsan`：

| 账号 / 权限 | 集群 | 北京时间 | 结果 |
|---|---|---|---|
| zhangsan，只读 | prod-a | 21:30 | 允许 |
| zhangsan，只读 | prod-a | 10:00 | 拒绝，不在允许时间内 |
| wangwu，只读 | prod-a | 21:30 | 拒绝，不在允许账号中 |
| zhangsan，只读 | 没有专属规则的集群 | 21:30 | 使用默认规则，默认关闭时拒绝 |
| 有「更新镜像」权限的账号 | 可访问的集群 | 任意 | 按操作权限直接执行 |

例外授权覆盖该集群下的所有命名空间和 Deployment。想让某人只更新镜像、不能做其他变更，可先在「用户与权限」中授予目标集群的「只读」权限，再配置此规则。

「权限与审批」中连「更新镜像」的管理员权限也被关闭时，相当于全站关闭该操作，例外规则不会绕过这个开关。

## 镜像仓库凭据

仓库凭据用于自动查询最新 20 个镜像标签。不配置凭据时仍可手动输入标签更新。

| 字段 | 如何填写 |
|---|---|
| 仓库域名 | 与镜像地址的域名一致，可带端口，如 `harbor.example.com:8443`；不填协议、路径或镜像名 |
| 适用集群 | `default` 表示该仓库的通用凭据，也可为特定 `K8S_NAME` 单独配置 |
| 用户名 / Access Key | Harbor 用户名、华为云 AK 或阿里云 AccessKey ID |
| 密码 / Secret Key | Harbor 密码、华为云 SK 或阿里云 AccessKey Secret |

| 仓库 | 域名示例 | 查询方式 |
|---|---|---|
| 华为云 SWR | `swr.cn-south-1.myhuaweicloud.com` | 使用 AK / SK 查询最近更新的镜像标签 |
| 阿里云 ACR | `registry.cn-shenzhen.aliyuncs.com` | 使用 AccessKey ID / Secret 查询镜像标签 |
| Harbor 2.x | `harbor.example.com` | 使用用户名 / 密码访问 Harbor API |

匹配顺序为：**仓库域名精确匹配 → 优先使用该集群凭据 → 没有专属凭据时使用同仓库的 default**。同一个域名和集群不能重复配置。

已有凭据只显示已配置状态，不返回原始值。编辑已有行时，凭据留空表示保留原值；新增行需要填写两项。要删除凭据，删除该行并保存。凭据在入库前使用安装时生成的 `AI_ENCRYPTION_KEY` 加密，备份或迁移数据库时应保留 `kubedoor-ai-security` Secret 和 `kubedoor.conf.ai-secrets`。

## Deployment 更新流程

1. 在 Deployment 列表找到目标服务，点击「操作 → 更新」。
2. 页面显示当前镜像及从仓库查询到的标签，可以搜索选择，也可以手动输入标签。
3. 只填写标签，例如 `v1.2.3`，不填写完整镜像地址。
4. master 校验当前账号的权限和例外规则，将请求交给目标集群的 Agent。
5. Agent 更新 Deployment 第一个容器的镜像标签并触发滚动更新；仓库和镜像名保持不变。

Agent 会通过该集群配置的 IM 通知推送开始、进度、Pod 异常、成功或超时。监控最长持续 20 分钟，超时不会自动回滚。同一 Deployment 再次更新时，上一次的监控会被取消。完整操作记录可在「系统管理 → 操作审计」中查看。

仓库标签获取失败时可手动填写标签。master 需要能访问仓库接口；Harbor 使用 HTTPS 并校验证书。Docker Hub、GHCR、ACR 企业版等未受支持的接口可能无法自动列出标签。

## 从旧配置升级

旧配置式部署更新 master 和 Web 镜像后，在 `tools/legacy-install` 目录运行 `./install.sh master -c /path/to/original/kubedoor.conf`。安装脚本会在覆盖旧 ConfigMap 前读取其中的 `UPDATE_IMAGE`、`REGISTRY_SECRET`，并读取本地 `kubedoor.conf` 中的旧 `UPDATE_IMAGE_JSON`、`REGISTRY_SECRET_JSON`；本地明确填写的值优先。

升级请使用安装命令完成迁移；`./install.sh render master` 只生成清单，不读取旧集群配置或执行数据库迁移。

旧设置通过标准输入交给新 master 导入数据库，不会写入新的 ConfigMap。导入只填充数据库中尚未存在的设置；页面已经保存过的配置（包括主动清空的配置）不会被旧值覆盖。迁移确认成功后，脚本会删除本地配置中的两个旧赋值。

为防止升级中断造成数据丢失，迁移期间会在原配置旁临时保存权限为 `0600` 的 `.image-settings-migration.json` 快照；该文件已被 Git 忽略。成功后自动删除；失败时保留原配置和快照，修复后重新执行安装即可继续。尚未完成迁移前不要手动删除这两份数据。

如果仅升级了 master 容器而保留旧环境变量，master 首次启动也会将旧环境变量导入尚未配置的数据库项。后续修改请统一使用管理页面。

## 常见问题

| 现象 | 检查位置 |
|---|---|
| 镜像标签列表为空 | 在「镜像仓库凭据」检查域名、适用集群和凭据；确认 master 能访问仓库，也可手动输入标签 |
| 只读账号更新被拒绝 | 检查账号对目标集群有只读权限、例外规则已开启、当前北京时间在允许时段、账号在白名单中 |
| 读写账号更新被拒绝 | 检查「权限与审批 → 更新镜像」是否允许该集群权限级别；例外规则不适用于读写账号 |
| 页面配置保存后未按新规则执行 | 重新查询页面确认保存成功；检查是否被该集群的专属规则覆盖默认规则，无需重启 master |
| 无法解密仓库凭据 | 恢复原 `AI_ENCRYPTION_KEY`，或在页面重新填写凭据并保存 |
| 更新没有 IM 通知 | 检查该集群 Agent 的 `MSG_TYPE`、`MSG_TOKEN` 配置和 Agent 日志 |
