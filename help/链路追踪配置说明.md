# 链路追踪配置说明

KubeDoor 的 AI 助手可以读取 Jaeger 链路，用来排查「某个接口为什么返回 400 / 502 / 504、为什么超时、为什么变慢」这类问题：先按服务、时间、状态码、耗时、Pod 等条件找到出问题的请求，再沿着调用链找出最先出错或最耗时的服务，最后结合 Pod 日志、事件、指标给出原因。

链路追踪在 **系统管理 → 链路追踪** 中配置，只有系统管理员能修改；配置保存在 PostgreSQL，保存后立即生效。对某个集群有只读及以上权限的账号，都可以让 AI 查这个集群的链路（网页 AI、企微 AI、外部 MCP 规则相同）。

## 前提

| 项目 | 要求 |
|---|---|
| Jaeger 版本 | **2.23 及以上**。KubeDoor 只使用 Jaeger 的 api_v3 HTTP 接口，搜索依赖 2.23 新增的结构化过滤和 `/api/v3/capabilities`；低于 2.23 时只能按链路 ID 查看 |
| 网络 | KubeDoor 控制端（kubedoor-master）能访问 Jaeger 的查询地址（默认端口 16686）；启用 ClickHouse 加速时还要能访问 ClickHouse 的 HTTP 端口（默认 8123） |
| 链路数据 | 应用已经接入 OpenTelemetry 并把链路写进 Jaeger；建议在链路的资源属性里带上集群标识（见下文「集群字段」） |

不需要开启 Jaeger 自带的 MCP（`extensions.jaeger_query.ai.mcp`），KubeDoor 不使用它。

## 配置步骤

### 1. Jaeger 连接

| 字段 | 如何填写 |
|---|---|
| Jaeger 查询地址 | 填 Jaeger UI 的地址即可，例如 `http://jaeger-query.observability:16686`；Jaeger 配置了 `base_path` 时把路径带上，例如 `https://ops.example.com/jaeger` |
| Jaeger UI 地址 | 可选。AI 回答里的链路链接用这个地址拼成 `<地址>/trace/<链路 ID>`，方便在浏览器里打开；不填时和查询地址相同。查询地址是集群内地址、浏览器打不开时填外部地址 |
| 请求头 | Jaeger 前面有鉴权代理时填写，例如 `Authorization: Bearer …`；值加密保存，页面只显示名称，编辑时留空表示沿用 |
| 超时 / 校验 HTTPS 证书 | 单次请求的超时时间；自签证书可以关闭证书校验 |

填好后点「测试连接」，页面会显示服务数量、Jaeger 版本是否满足要求，以及存储后端支持的搜索能力。

### 2. 集群字段

一个 Jaeger 往往保存多个 K8S 集群的链路。KubeDoor 用链路**资源属性**里的一个字段区分集群：AI 在某个集群里提问时，搜索只返回这个集群的链路。

**怎么填**：看应用是怎么把集群标识写进链路的。

- 在 OTel Agent 的环境变量里自己加的，例如：

  ```yaml
  env:
    - name: OTEL_RESOURCE_ATTRIBUTES
      value: k8sname=cassmall-prod-penglai
  ```

  这里 `k8sname` 就是字段名，「集群字段」填 `k8sname`。
- 用 OpenTelemetry Operator 或 Collector 的 `k8sattributes` / `resource` 处理器加的，一般是 `k8s.cluster.name`。
- 不确定时，用页面下方的「识别字段」取几条链路，页面会列出取值能对上 KubeDoor 集群名或别名的资源属性，点「设为集群字段」即可。

**取值怎么匹配**：链路里的取值要等于 KubeDoor 里的**集群名**，或这个集群的某个**别名**（在「Agent 管理」页维护别名）。例如 KubeDoor 里集群名是 `prod-penglai`，链路里写的是 `cassmall-prod-penglai`，就给 `prod-penglai` 加一个别名 `cassmall-prod-penglai`。页面会列出每个集群的名称和别名，以及测试时在链路里看到的取值对上了哪个集群；对不上的取值会提示去加别名。

集群字段留空表示不按集群过滤（Jaeger 里只有一个集群时可以这样）。按链路 ID 查看时会返回整条链路，包括其他集群的 Span，每个 Span 标注所属集群。

### 3. 字段映射

OpenTelemetry 新旧两版语义约定的字段名不同（例如状态码是 `http.response.status_code` 或 `http.status_code`），不同语言、不同版本的探针也不一样。字段映射告诉 KubeDoor 每类信息可能存在哪些字段里，搜索时会同时匹配所有候选字段名：

| 字段 | 默认候选 |
|---|---|
| HTTP 状态码 | `http.response.status_code`、`http.status_code` |
| 请求方法 | `http.request.method`、`http.method` |
| 路由模板 | `http.route` |
| 请求路径 | `url.path`、`http.target` |
| 完整 URL | `url.full`、`http.url` |
| 查询参数 | `url.query` |
| 域名 / 被调方地址 | `server.address`、`http.host`、`net.host.name`、`net.peer.name` |
| 客户端 IP | `client.address`、`http.client_ip`、`net.sock.peer.addr` |
| 异常类型 | `exception.type`（异常事件的属性） |
| Pod | `k8s.pod.name`、`host.name` |
| 命名空间 | `k8s.namespace.name` |
| Deployment | `k8s.deployment.name` |

一般不用改。应用用了自定义字段名时，在对应行里添加；「识别字段」也会根据实际出现的字段给出建议，可以一键套用。

### 4. 业务字段

应用在链路里记录了业务标识（例如订单号、用户 ID）时，在这里登记字段名和中文说明，例如 `biz.order_no` = 订单号。AI 听到「订单号 SO2026…」时就知道按哪个字段查。

### 5. 打码字段

AI 查看 Span 详情时，这些字段的值会换成 `***`，不会发给模型服务商。内置已经打码 `authorization`、`cookie`、`token`、`password`、`secret`、`api-key` 等字段，以及 URL 里同名的查询参数和 `用户名:密码@`；这里可以再添加。

## ClickHouse 加速（可选）

Jaeger 使用 ClickHouse 存储时，Jaeger 的查询接口有几个限制，会影响排查：

| 限制 | 影响 | KubeDoor 不开加速时的处理 |
|---|---|---|
| 属性不能比较大小 | 不能直接查「状态码 ≥ 500」 | 展开成具体状态码逐个匹配 |
| 没有模糊匹配 | 不能查「URL 参数里包含某个订单号」 | 拉一批链路逐条检查，有扫描上限 |
| 搜索结果不按时间排序 | 结果不一定是最新的 | 按时间分段、从新到旧查询 |
| 不能做统计 | 回答不了「从几点开始、占多大比例、集中在哪个 Pod」 | 改用指标（Prometheus / VictoriaMetrics）查 |

开启加速后，KubeDoor 直接查 ClickHouse 里的一张扁平搜索表：状态码可以比较大小，URL 和查询参数可以模糊匹配，能按时间取最新的请求，AI 还多了按时间、Pod、接口、状态码分组的统计工具。查看单条链路仍然走 Jaeger 接口。

### 建表

搜索表由物化视图在 Span 写入时实时生成，只对建表之后写入的链路生效。下面以单机 ClickHouse、Jaeger 的库名为 `jaeger` 为例：

- 把 `k8sname` 换成你的集群字段名；
- TTL 按链路保留时间调整，`864000` 秒即 10 天；
- Jaeger 自带的表结构不用改。

```sql
-- 搜索表：每个 Span 一行
CREATE TABLE IF NOT EXISTS jaeger.trace_search
(
    `start_time` DateTime64(3),
    `trace_id` String,
    `span_id` String,
    `k8s_cluster` LowCardinality(String),
    `namespace` LowCardinality(String),
    `service_name` LowCardinality(String),
    `kind` LowCardinality(String),
    `span_status` LowCardinality(String),
    `operation` String,
    `url_path` String,
    `http_method` LowCardinality(String),
    `http_status` Int64,
    `duration_ms` Float32,
    `peer` String,
    `pod` String,
    `url_query` String,
    INDEX idx_trace_id trace_id TYPE bloom_filter(0.01) GRANULARITY 4,
    INDEX idx_path url_path TYPE bloom_filter(0.01) GRANULARITY 4,
    INDEX idx_operation operation TYPE bloom_filter(0.01) GRANULARITY 4,
    INDEX idx_duration duration_ms TYPE minmax GRANULARITY 1,
    INDEX idx_status http_status TYPE minmax GRANULARITY 1
)
ENGINE = MergeTree
PARTITION BY toDate(start_time)
ORDER BY (k8s_cluster, namespace, service_name, kind, start_time)
TTL start_time + toIntervalSecond(864000);

CREATE MATERIALIZED VIEW IF NOT EXISTS jaeger.trace_search_mv TO jaeger.trace_search AS
SELECT
    start_time,
    trace_id,
    id AS span_id,
    resource_str_attributes.value[indexOf(resource_str_attributes.key, 'k8sname')] AS k8s_cluster,
    resource_str_attributes.value[indexOf(resource_str_attributes.key, 'k8s.namespace.name')] AS namespace,
    service_name,
    kind,
    status_code AS span_status,
    name AS operation,
    if(str_attributes.value[indexOf(str_attributes.key, 'url.path')] != '',
       str_attributes.value[indexOf(str_attributes.key, 'url.path')],
       splitByChar('?', str_attributes.value[indexOf(str_attributes.key, 'http.target')])[1]) AS url_path,
    if(str_attributes.value[indexOf(str_attributes.key, 'http.request.method')] != '',
       str_attributes.value[indexOf(str_attributes.key, 'http.request.method')],
       str_attributes.value[indexOf(str_attributes.key, 'http.method')]) AS http_method,
    if(int_attributes.value[indexOf(int_attributes.key, 'http.response.status_code')] != 0,
       int_attributes.value[indexOf(int_attributes.key, 'http.response.status_code')],
       int_attributes.value[indexOf(int_attributes.key, 'http.status_code')]) AS http_status,
    duration / 1000000 AS duration_ms,
    multiIf(str_attributes.value[indexOf(str_attributes.key, 'server.address')] != '', str_attributes.value[indexOf(str_attributes.key, 'server.address')],
            str_attributes.value[indexOf(str_attributes.key, 'net.peer.name')] != '', str_attributes.value[indexOf(str_attributes.key, 'net.peer.name')],
            str_attributes.value[indexOf(str_attributes.key, 'db.name')] != '', str_attributes.value[indexOf(str_attributes.key, 'db.name')],
            str_attributes.value[indexOf(str_attributes.key, 'messaging.destination.name')]) AS peer,
    resource_str_attributes.value[indexOf(resource_str_attributes.key, 'k8s.pod.name')] AS pod,
    substring(multiIf(
        str_attributes.value[indexOf(str_attributes.key, 'url.query')] != '', str_attributes.value[indexOf(str_attributes.key, 'url.query')],
        position(str_attributes.value[indexOf(str_attributes.key, 'http.target')], '?') > 0, substring(str_attributes.value[indexOf(str_attributes.key, 'http.target')], position(str_attributes.value[indexOf(str_attributes.key, 'http.target')], '?') + 1),
        position(str_attributes.value[indexOf(str_attributes.key, 'url.full')], '?') > 0, substring(str_attributes.value[indexOf(str_attributes.key, 'url.full')], position(str_attributes.value[indexOf(str_attributes.key, 'url.full')], '?') + 1),
        position(str_attributes.value[indexOf(str_attributes.key, 'http.url')], '?') > 0, substring(str_attributes.value[indexOf(str_attributes.key, 'http.url')], position(str_attributes.value[indexOf(str_attributes.key, 'http.url')], '?') + 1),
        ''), 1, 1024) AS url_query
FROM jaeger.spans;

-- 汇总表：每 10 分钟各接口的 Span 数，用来列出服务和接口（可选，不建也能用加速）
CREATE TABLE IF NOT EXISTS jaeger.trace_search_dim
(
    `bucket` DateTime,
    `k8s_cluster` LowCardinality(String),
    `namespace` LowCardinality(String),
    `service_name` LowCardinality(String),
    `kind` LowCardinality(String),
    `operation` String,
    `url_path` String,
    `spans` UInt64
)
ENGINE = SummingMergeTree(spans)
PARTITION BY toDate(bucket)
ORDER BY (k8s_cluster, namespace, service_name, kind, operation, url_path, bucket)
TTL bucket + toIntervalSecond(864000);

CREATE MATERIALIZED VIEW IF NOT EXISTS jaeger.trace_search_dim_mv TO jaeger.trace_search_dim AS
SELECT
    toDateTime(toStartOfInterval(start_time, toIntervalSecond(600))) AS bucket,
    resource_str_attributes.value[indexOf(resource_str_attributes.key, 'k8sname')] AS k8s_cluster,
    resource_str_attributes.value[indexOf(resource_str_attributes.key, 'k8s.namespace.name')] AS namespace,
    service_name,
    kind,
    name AS operation,
    if(str_attributes.value[indexOf(str_attributes.key, 'url.path')] != '',
       str_attributes.value[indexOf(str_attributes.key, 'url.path')],
       splitByChar('?', str_attributes.value[indexOf(str_attributes.key, 'http.target')])[1]) AS url_path,
    count() AS spans
FROM jaeger.spans
GROUP BY bucket, k8s_cluster, namespace, service_name, kind, operation, url_path;
```

**ClickHouse 集群部署**（Jaeger 读写分库，例如写入库 `jaeger_local` 是本地表、查询库 `jaeger` 是 Distributed 表）：

1. 把上面四条语句里的 `jaeger.` 换成写入库 `jaeger_local.`，包括物化视图的 `FROM jaeger_local.spans`。在每个节点上执行，或者加 `ON CLUSTER <集群名>`。
2. 在查询库建同名的 Distributed 表：

```sql
CREATE TABLE jaeger.trace_search ON CLUSTER 'ck-ops' AS jaeger_local.trace_search
ENGINE = Distributed('ck-ops', 'jaeger_local', 'trace_search', rand());
CREATE TABLE jaeger.trace_search_dim ON CLUSTER 'ck-ops' AS jaeger_local.trace_search_dim
ENGINE = Distributed('ck-ops', 'jaeger_local', 'trace_search_dim', rand());
```

KubeDoor 里填查询库（`jaeger`）。

### 只读账号

建议给 KubeDoor 单独建一个只读账号，不要用 Jaeger 写数据的账号：

```sql
CREATE USER IF NOT EXISTS kubedoor_ro IDENTIFIED WITH sha256_password BY '<密码>' SETTINGS readonly = 2;
GRANT SELECT ON jaeger.trace_search TO kubedoor_ro;
GRANT SELECT ON jaeger.trace_search_dim TO kubedoor_ro;
-- 集群部署：Distributed 表会去各节点查本地表，本地表也要授权，且用户要在每个节点上都存在（加 ON CLUSTER）
GRANT SELECT ON jaeger_local.trace_search TO kubedoor_ro;
GRANT SELECT ON jaeger_local.trace_search_dim TO kubedoor_ro;
```

`readonly = 2` 表示只能查询，但允许 KubeDoor 为每条查询设置超时和结果行数上限。账号设成 `readonly = 1` 也能用，只是不能设置这些上限。

### 在 KubeDoor 里配置

在「链路追踪 → ClickHouse 加速」里打开开关，填 HTTP 地址（例如 `http://10.0.0.88:8123`）、库名（`jaeger`）、搜索表（`trace_search`）、汇总表（`trace_search_dim`，没建可以留空）、账号和密码（加密保存）。点「测试」检查：能否连上、表里是否有需要的列，以及最近 10 分钟每个集群取值的 Span 数，并标出对上了哪个 KubeDoor 集群。

## AI 怎么用

在 AI 助手里直接问，例如：

- 「order-service 的 /api/order/submit 最近一小时为什么 502」
- 「deploy-gateway-api 刚才的 504 从几点开始的，集中在哪个 Pod」
- 「traceId 0043c22a5e5b5ca8e0c3e8885c6f3f29 为什么这么慢」
- 「订单号 SO20261121001 的请求报错了，查一下链路」

AI 会按需列出服务和接口、按条件搜索链路、统计（开了 ClickHouse 加速时），再取出具体的链路分析：

- 请求最终是失败还是已恢复（中间出错、重试后成功的，不当成失败原因）；
- 出错链路和最可能的根因 Span；
- 时间花在哪几个 Span 上（关键路径）；
- 有没有大量串行的重复调用（N+1）。

找到根因所在的 Pod 后，AI 会接着查它当时的日志、重启记录、事件和指标。回答里附 Jaeger 链接，可以点开核对。

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 提示「还没有配置链路追踪」 | 系统管理员在「系统管理 → 链路追踪」填好 Jaeger 地址并打开启用开关 |
| 提示「搜索需要 Jaeger 2.23 及以上」 | 升级 Jaeger；低于 2.23 只能按链路 ID 查看。Jaeger 2.20 使用 ClickHouse 存储时，搜索可能报「Query memory limit exceeded」，也是升级到 2.23 解决 |
| 搜不到明明出过错的请求 | 请求可能没被采样，或者服务没接入链路；集群字段的取值和 KubeDoor 集群名、别名对不上时，所有搜索都会是空的，在页面用「测试」或「识别字段」核对 |
| Jaeger UI 里填 `error=true` 搜不到报错链路 | Jaeger 使用 ClickHouse 存储时的已知问题（上游 #9184）。KubeDoor 按 Span 状态搜索，不受影响 |
| 按链路 ID 查看比较慢 | Jaeger 按 ID 查找时如果不知道时间范围，要扫描全部数据。AI 会先从最近的时间范围找；用户提供大概时间会更快 |
| ClickHouse 测试提示缺少列 | 搜索表的列名和类型要和上面的建表语句一致；物化视图只处理建表之后写入的数据 |
