// 01 · 架构

控制端一套，集群端按需扩展

控制端由网页向导一次装好，集群端在网页上传 kubeconfig 接入；两者可以装在同一个集群（单集群场景），也可以分开部署，纳管任意多套 Kubernetes。

  • 内置 AI 运维助手

    选定集群用一句话排障与运维，自动联合日志、事件、监控与历史数据定位原因，还能读服务源码、查运行配置；变更先冻结参数、展示差异，按「权限与审批」人工批准后才执行，会话与每次操作全程入库审计，模型自由选。同一能力也开放给企业微信机器人和标准 MCP。

  • Agent 主动外连

    每个业务集群的 kubedoor-agent 主动以 WebSocket 连接 master（同集群走 Service，跨集群经 Web 入口），网页安装为每个集群生成独立的 Agent 账号；vmagent 直接远程写入时序库，控制端默认无需反向访问业务集群。

  • 单一 PostgreSQL

    管控配置、高峰资源、K8S 事件、告警记录、Istio 路由、AI 会话，以及权限、通知、接口等界面配置都存在 PostgreSQL 原生表，不依赖扩展；启动自动建表，库不存在时安装向导自动创建。

  • 时序库独立 · 告警可选

    时序库必需（Deployment 列表、资源总览与高峰采集都依赖它）：独立部署的 VictoriaMetrics 单机版或集群版，也可用已有的。Grafana 看板随控制端安装，vmalert、Alertmanager 与告警服务一个开关一起装或不装。

// 02 · AI 运维助手

会排障，更守规矩的 K8S 运维助手

在 Web 顶部打开「AI 助手」，选定一个集群，用一句话描述问题。助手自动选择数据来源，联合日志、事件、监控与历史数据定位原因，还能读服务源码、查运行配置；任何变更都先冻结参数并展示变更预览（K8S API 写入附服务端 Dry-run 差异），按「权限与审批」人工批准后才执行。

一句话运维 K8S

选定集群即可用自然语言提问，每轮只操作所选集群；统一网关覆盖 73 项 KubeDoor 业务操作与 8 类通用执行器，查询类自动执行。

  • K8S API / CRD
  • kubectl
  • istioctl
  • jq · yq · curl · dig · openssl · rg
  • Pod exec
  • MySQL · Redis · ES 只读

例如这个服务最近频繁重启，结合日志、事件和监控帮我找原因

先审批，再执行

KubeDoor 业务操作与 Pod 内命令展示准确参数和变更预览；通用 K8S API 写入与 kubectl apply 另附服务端 Dry-run 配置差异。批准后按冻结参数原样执行，模型无法偷换。

平台能力优先

重启、扩缩容、定时 / 周期任务与资源管控优先走 KubeDoor 已验证的接口，覆盖不到才用通用工具，不让模型凭空拼 YAML。

  • restart_deployment
  • scale_deployment
  • cron_deployment_restart
  • resource_config_update

绝不盲目重放

超时或断线导致写入结果未知时，标记「执行结果不确定」，本轮不再执行任何写操作、也不会换通道重试，需先查询实际状态；服务重启也不会重发已派发的操作。

模型自由选

任意兼容 OpenAI Chat Completions、支持工具调用的模型均可接入，含免鉴权的自建模型；DeepSeek 思考模式专项适配，「测试连接」实测工具调用。

Agent 优先 · 自动直连

通用操作优先经在线 Agent 在业务集群里执行（master 复核、Agent 二次校验）；网页安装 Agent 时自动配置该集群的 kubeconfig（AES-256-GCM 加密保存），Agent 离线照样可用。

历史 + 实时 + 监控联合分析

入库的资源与 JVM 快照、历史事件与告警，加上实时日志、事件与 VictoriaMetrics 自由 MetricsQL 查询，服务端强制限定当前集群。

全局记忆 · DeepAgents

会话一键总结为可编辑的经验草稿，审核后存入全局记忆、下一轮按需引入；基于 DeepAgents，内置 K8S 运维、源码分析、运行配置三个 Skill，子 Agent 并行调查。

认得资源管控2.3

扩缩容、调整 requests / limits 与 JVM 前先查 Deployment 是否受准入控制管控：受管控的走管控表，不受管控的直接改；审批卡写明「当前 → 目标」与副作用，执行后回读核验，会被改回的直接修改在批准前就拦下。

长对话省钱 · 用量可见2.3

系统提示与历史保持稳定，长对话持续命中模型的前缀缓存；上下文按模型窗口自动压缩、对话框显示占用比例；「AI 用量看板」统计用量、缓存命中率与估算费用，DeepSeek 思考强度可调。

一键问 AI · 重新生成2.3

告警、K8S 事件、Deployment 与 Pod 菜单一键「问 AI」，自动带上集群、资源和告警原文；最后一轮可重新生成或编辑后重发，会话按标题和内容搜索。

读源码定位问题2.6

按 Deployment 或 Pod 查当前镜像的代码链接；管理员允许后，AI 下载当前版本源码，按日志里的异常用 ripgrep 搜索、ctags 找定义、逐行阅读，指出出错的代码行。

查运行配置 · 只读查库2.6

获取服务实际运行的配置，密码换成占位符，模型看不到明文；再用配置里的连接信息只读查询 MySQL、Redis、Elasticsearch，由服务端填入密码、只连配置里的地址。

接入你自己的 MCP2.6

对话框「MCP 管理」接入自己的 SSE / Streamable HTTP MCP 服务（工单、知识库等），按账号隔离、加密保存；只读工具自动执行，其余按设置审批。

// 2.6 新增 · 读代码 · 查配置

从报错堆栈，直达出错的代码行

对接你自己的「获取代码接口」和「获取运行配置接口」：Deployment、Pod 菜单里一键打开当前镜像对应的代码、查看服务实际生效的配置；管理员允许后，AI 助手也用它们排障。

  • 接口按镜像返回代码页面、源码下载和最近 Commit；AI 下载当前版本源码，用 ripgrep 搜索、ctags 找定义、逐行阅读
  • 运行配置是配置中心、环境变量与配置文件合并后的生效值；交给模型前密码、密钥换成占位符，明文不发给模型服务商
  • 用配置里的连接信息只读查询 MySQL、Redis、Elasticsearch：只读语句与命令白名单，只连配置里写的地址，默认每次要批准
  • AI 读源码、取配置的开关默认关闭，每次获取都记入操作审计

// 安全护栏

每一次变更，都可审批、可追溯

  1. 1只读查询自动执行
  2. 2变更请求冻结完整参数
  3. 3变更预览API 写入附 Dry-run 差异
  4. 4批准执行30 分钟内有效
  5. 5派发账本同一动作只派发一次
  6. 6结果核验不确定就先查询，不重放
  • 按集群 × 操作授权，没有权限的变更直接拒绝，要不要审批按操作配置
  • 所选集群是本轮硬边界
  • Pod 内命令按清单分查看 / 其他 / 高危，高危命令固定审批
  • 参数数组执行，不开放 shell
  • 模型 API Key 不落服务端，流式输出、checkpoint 与日志中全程脱敏
  • 运行配置里的密码换成占位符，查库时由服务端填入
  • 数据查询只读：单条查询语句、只读命令与查询接口白名单
  • 「自动批准执行」需手动勾选，勾选后需要审批的操作（含高危命令）自动批准，仅当前页面有效
  • 会话、动作与事件全部入库

// 03 · 全栈能力

一个平台，管好多套 K8S

从监控大屏到准入控制，从实时日志到节点均衡，覆盖 K8S 日常运维的完整链路；其中的查询与运维操作，大多也能直接交给 AI 助手完成。

多集群统一监控 · 总览大屏 · Grafana

资源总览大屏汇总各集群的节点、工作负载、Pod 与 PVC，标出风险节点、Top10 异常告警与事件，30 秒自动刷新；另内嵌 K8S、节点与高峰资源三套 Grafana 看板。各集群的 vmagent 把指标直接写入独立部署的 VictoriaMetrics（单机版或集群版），也可对接已有的时序库。

K8S 资源管理

Deployment、Pod、Service、Ingress、ConfigMap、StatefulSet、DaemonSet 与节点统一管理，Monaco 在线编辑 YAML，支持批量删除、扩缩容与重启；网页终端可直接进容器或宿主机。

获取代码 · 获取运行配置2.6

对接你自己的接口：Deployment、Pod 操作菜单里一键打开当前镜像对应的代码页面、源码下载和最近 Commit，或查看服务实际运行的配置（配置中心、环境变量、配置文件合并后的生效值）。接口地址和请求头在「系统管理」里配置，请求头加密保存，每次获取记入审计；AI 助手也用它们读代码、查配置。

  1. 菜单一键获取Deployment · Pod 操作菜单
  2. 调用你的接口带上集群、命名空间、服务与镜像
  3. 代码链接 · 生效配置弹窗展示，AI 也能用

消息通知2.6

企业微信、钉钉、飞书、Slack 在「系统管理 → 消息通知」配置，token 加密保存；全局默认群之外可按集群单独配群，保存即生效、可发测试消息。事件告警与运维通知由 master 统一发送，agent 断线时暂存补发。

实时状态 · Pod 日志

Deployment 就绪与滚动状态经 K8S Watch 实时推送；Pod 日志实时跟随，异常多色标记、关键字定位，可按容器或整个 Deployment（全部 Pod 聚合）查看，单个 Pod 的完整日志可 gzip 下载。

发布管控

镜像更新自动列出仓库最近 20 个标签（阿里云 ACR、华为云 SWR、Harbor）；只读账号可按集群、时段与用户授权发布，进度推送 IM。

定时任务 · Pod 隔离 · 弹性

扩缩容与重启支持立即、定时、周期执行；Pod 一键隔离保留现场，可同时临时扩容、调度到指定节点；支持华为云 CCI 弹性扩容。

告警聚合 · 事件告警 · 告警屏蔽

内置 44 条告警规则，Pod 告警按日聚合、可标记处理；K8S 事件全量入库并按 JSON 规则告警；指标告警支持 Alertmanager 风格屏蔽（= != =~ !~），命中仍入库留痕。

高峰资源画像 · 准入控制

每天采集业务高峰时段的资源数据，取近 10 天集群 CPU 总消耗最大的一天写入管控表；在「Agent管理」开启「准入控制」后，Deployment 创建与发布时由 Mutating Webhook 按管控表改写副本数、第一个容器的 requests / limits 与 JVM 参数，扩缩容（含 kubectl 直接改副本数）只改写副本数，让资源申请与真实使用保持一致。

  1. 每日高峰采集CPU / 内存取 P80
  2. 近 10 天最大日写入管控表
  3. 准入 Webhook改写副本数 · requests · limits · JVM

JVM 参数管控 · Java 诊断

采集并管控 Xms、Xmx、Xss、MaxMetaspaceSize，开启准入控制后在下次发布或重启时替换已有参数；展示堆与 G1 Eden 使用率，一键 Dump、Jstack、JFR。

节点负载均衡

按节点 CPU 极差判断失衡，迭代生成迁移计划（整体标准差下降才采纳），分批隔离式迁移并轮询新 Pod 就绪；手动触发，需 metrics-server。

账号 · 权限与审批2.6

本地账号与 LDAP 统一登录，按用户 × 集群授权「管理员 / 读写 / 只读 / 无」；「权限与审批」按 27 类操作配置每级权限能做什么、AI 变更要不要审批，Web、Grafana、AI 助手、企微与 MCP 共用一套；登录、权限变更与所有写操作（含越权被拒）进入操作审计。

Istio VirtualService 管理2.3

按「Istio 组」统一维护一个项目在多个集群里的 VirtualService：规则、默认路由与 gateways 全组共用一份标准，hosts 和规则里的域名条件按集群维护；矩阵一屏看清各集群是否一致，跨组冲突标红。2.6 起改集群前自动备份、可一键回退，同集群的域名冲突自动检查，集群现状里的规则可挑着同步回组标准。

  1. 刷新现状并行采集各集群的 VirtualService
  2. 对比 · 纳管规则按匹配条件对齐，一致的一键纳管
  3. 预览后下发按集群生成，逐项展示差异

CoreDNS 管理2.3

像改表格一样维护 CoreDNS 的 hosts 自定义解析，只重写改动的行；保存前看差异，并发修改自动提示冲突，保存后从集群内检查解析是否生效；另有解析测试、端口测试与 Monaco 高级编辑。

// 账号 · 权限与审批

权限细到每个集群、每类操作

登录、会话与权限由 master 统一管理，nginx 只做反向代理：Web、Grafana、AI 助手与 MCP 共用一个入口、一套账号、一套权限。

  • 本地账号 + LDAP：Web 上配置并一键测试，本地账号优先，LDAP 用户首次登录自动开通
  • 全局角色「系统管理员 / 集群管理员 / 读写 / 只读 / 无」兜底，再按用户 × 集群单独授权「管理员 / 读写 / 只读 / 无」，单独授权优先
  • 「权限与审批」按 27 类操作勾选每级权限能不能做、AI 做之前要不要批准；Pod 内命令按查看 / 其他 / 高危分类，高危命令固定审批2.6
  • 「无」权限的集群在页面、下拉框、告警与 AI 助手中都不可见；登录、权限变更和所有写操作（含越权被拒）进入操作审计
  • 水墨登录页：HttpOnly 会话、7 天内免登录、连续输错自动锁定

// 05 · 一键安装

一条命令，网页向导装好全部

不用 Helm，不用编辑配置文件，执行机器只要 sh 和 kubectl，没有 kubectl 也能用脚本生成 YAML 部署。一条命令启动安装向导，在浏览器里填好数据库、时序库和管理员密码，控制端各服务一起自动部署、逐项验证；其他集群在网页上传 kubeconfig 接入。

  • 前置条件
  • K8S ≥ 1.21
  • shkubectl 可选，可导出 YAML
  • PostgreSQL已有或 Docker Compose
  • VictoriaMetrics单机版或集群版
  • metrics-server用量列、节点均衡
  • 镜像仅 amd64
  1. 01

    一条命令启动向导

    把单文件 install.sh 放到能用 kubectl 连上集群的机器执行，不需要 Python 或完整源码。脚本在 kubedoor 命名空间启动 Web 和临时安装服务，打印访问地址和一次性安装密钥；镜像仓库和版本写在脚本顶部，内网可用 --image-repo、--tag 覆盖。没有 kubectl 也能装：用 --export 生成 YAML，导入 K8S 管理平台或云控制台即可部署。

    curl -fsSLO \
  https://raw.githubusercontent.com/CassInfra/KubeDoor/main/deploy/install.sh
sh install.sh
    # 输出（示意）
Web 入口：http://192.168.1.10:31080
一次性安装密钥：********
打开网页，按向导填写数据库和管理员信息。
    curl -fsSLO \
  https://raw.githubusercontent.com/CassInfra/KubeDoor/main/deploy/install.sh
sh install.sh --export kubedoor-install.yaml --nodeport 30080
    # 导出不连接集群，任何有 sh 的机器都能执行；然后：
1. 把 kubedoor-install.yaml 导入目标集群
   （管理平台 / 云控制台的 YAML 创建，或 kubectl apply -f）
2. 打开 http://<K8S 节点 IP>:30080
3. 安装密钥：Secret kubedoor-setup-auth 的 SETUP_KEY
  2. 02

    网页里点完六步

    环境检查 → PostgreSQL → 时序数据库 → 基础设置 → 自动安装 → 安装 Agent。库不存在时自动创建，时序库读写地址自动生成，访问地址自动获取；控制端各服务一起部署，每个服务单独显示状态和失败原因，全部检查通过才报成功，收尾时停用安装服务、撤销临时权限。

  3. 03

    网页接入更多集群

    控制端所在集群的 Agent 可在向导最后一步顺手装好。其他集群由管理员在「Agent管理」→「安装 Agent」上传 kubeconfig、确认集群标识即可安装：进度逐步显示，Agent 上线和指标写入都会验证，并自动配置该集群的 AI Kubeconfig。

还没有数据库和时序库？

仓库的 deploy/postgres、deploy/victoria-metrics 各带一份 Docker Compose：复制 .env.example、改掉密码后 docker compose up -d，不用手动建表。已有的 PostgreSQL 和 VictoriaMetrics 直接填进向导即可。

内网与离线

--image-repo、--tag、--image-pull-secret 改用内网镜像，导出的 YAML 同样带上这些设置，可以拷进内网部署。刷新或关闭网页不会中断安装，失败可修好后重试。

从旧版本升级

网页向导只做全新安装。2.x 的配置式部署继续用 tools/legacy-install 升级，通知改在「消息通知」页面配置；1.x（Helm）请先关闭准入控制、helm uninstall 后全新安装。详见 完整部署文档。
